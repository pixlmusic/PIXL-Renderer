# PIXL DLSS Neural Rendering (Experimental)

## Status

PIXL Renderer can optionally evaluate the NVIDIA DLSS Neural Rendering 310.8 runtime through PIXL's existing D3D11-to-D3D12 presentation sidecar. The feature is disabled by default and ordinary DLSS remains the fallback image for every discovery, initialization, resource, or evaluation failure.

This is an experimental integration of a private, versioned NGX Feature 18 contract. It is not part of the public Streamline 2.10.3 API shipped by the current project. PIXL therefore accepts only the locally validated `nvngx_dlssnr.dll` 310.8.x runtime and refuses unknown versions instead of guessing their parameter ABI.

## Architecture

```text
Skyrim D3D11 opaque/effects/post pipeline
                |
        PIXL EncodeTexturesCS
        - typed depth guide
        - dilated DLSS motion guide
                |
        normal Streamline DLSS
                |
      final SDR PIXL back buffer
                |
    D3D11/D3D12 shared resources
                |
 PIXL DX12 sidecar command list/queue
                |
 optional DLSSNR Feature 18 evaluation
        | failure          | success
        v                  v
 normal DLSS frame     NR output (double buffered)
        \                  /
          real swap chain
                |
      optional FSR frame generation
```

No second D3D12 device, queue, allocator, or presentation wrapper is created. Neural Rendering records on the command list already owned by `DX12SwapChain`, after the D3D11-to-D3D12 fence and before the sidecar copies into the real swap-chain buffer.

The full-size shared depth and motion resources contain the current dynamic-resolution render subrect. PIXL passes the actual subrect dimensions and uses the motion-vector texture generated by `EncodeTexturesCS`, not Skyrim's untreated motion target. When frame generation is also active, it retains its own raw pre-upscale guide pair while Neural Rendering uses a separate post-DLSS encoded guide pair; neither feature overwrites the other's inputs.

Two shared neural output textures alternate with the swap-chain back-buffer index. This lets D3D11 Photo Finish copy the last completed neural result while D3D12 writes the next result, avoiding a cross-API read/write race at the nested Present boundary.

## Runtime discovery

The primary runtime location is:

```text
Data/Shaders/ImageReconstruction/Streamline/nvngx_dlssnr.dll
```

Legacy PIXL Streamline locations are searched only as fallbacks. Loading is dynamic, so the DLL is not a plugin dependency and its absence cannot prevent `PIXLRenderer.dll` from loading.

The 310.8 runtime expects the signed NGX core identity during its internal validation. PIXL temporarily patches only the loaded DLSSNR module's `GetModuleFileNameW` import slot while making the relevant vendor call, immediately restores the import, and disables NR if the scoped operation cannot be established. This behavior is confined to the optional runtime bridge.

## User controls

The Image Reconstruction page exposes an experimental DLSS Neural Rendering section when DLSS is selected:

- Enable Neural Rendering (restart required)
- Preset: Natural, Balanced, Detail, Strong / Experimental, Custom
- NR Intensity: 0.0-2.0
- Local Tone: 0.0-2.0
- Local Structure: 0.0-2.0
- Skin Structure: 0.0-2.0
- Model Style: 0-3
- NR Quality Contract: follow current DLSS, DLAA, Quality, Balanced, Performance, Ultra Performance, Ultra Quality
- NR Output Preset: runtime default, Preset 1, Preset 2, Preset 3
- Automatic Character Mask
- UI Correction

`Natural` is the restrained initial test preset and the default configuration remains disabled.

The quality contract writes the standard NGX `PerfQualityValue`; the output preset writes the installed runtime's `DLSSNR.Hint.Render.Preset`. Both are feature-creation inputs and require a restart. The default follows PIXL's current DLSS mode and leaves the output preset to the runtime.

PIXL does not expose an INT4 switch. Binary inspection of the installed 310.8 runtime found FP8/FP16 execution paths, but no INT4 kernels or application-facing precision parameter. A driver/runtime override must remain owned by NVIDIA; inventing `DLSSNR.Precision` would be a silent no-op or an ABI risk.

Standard DLSS SR preset E is also not exposed. Streamline 2.10.3 and its bundled NVIDIA headers explicitly remove E and resolve unsupported presets to Default. PIXL now lists only the presets that this runtime actually honors: Default, J, K and F. The previously visible L/M entries were similarly removed because this Streamline version resolves them to Default.

Photo Mode adds a separate **Neural Final Composite** toggle in both the full Director workspace and the `Insert` quick panel. The preference remains editable before the first completed neural frame; `READY` means the live Feature 18 output is available, while `ARMED` means the preference is saved and the universal Photo Finish path will be used unless a neural session becomes available. TAA, FSR, native rendering and non-DLSS GPUs therefore keep the normal Photo Finish workflow unchanged.

When enabled and available, every deterministic jittered Photo Finish phase waits for a distinct completed neural frame before it is copied. Neural capture enforces a minimum eight-frame convergence burst, even if an older configuration requested one or four frames; the `Neural Accumulation` control can select 8, 16 or 24 fresh frames. The frames are accumulated once in PIXL's jitter-aware still-image resolve rather than recursively feeding model output back through the private transformer. This improves convergence and preservation of stable detail without compounding hallucinated structure. Native / 2x / 4x continues to control the final saved-photo resolution; the private runtime itself remains bounded to its validated display-resolution output contract.

## Current compatibility gates

The native PIXL path runs only when all of the following are true:

- DLSS is the selected reconstruction method.
- Neural Rendering was enabled when the process created the swap chain.
- the PIXL DX12 sidecar is active;
- `nvngx_dlssnr.dll` reports version 310.8.x and exports the required D3D12 entry points;
- if Frame Generation is enabled, its dedicated raw guide resources and runtime remain healthy;
- PIXL HDR output is off (validated path is SDR only);
- `renodx-dlss.addon64` is not loaded.

RenoDX and PIXL native NR must not process the same frame. PIXL detects the loaded addon and bypasses its own evaluator rather than risking double enhancement.

## Fail-safe behavior

Missing or unsupported runtime files, missing exports, NGX initialization failures, resource failures, and evaluation errors all preserve the ordinary DLSS result. Runtime faults latch for the session to avoid repeated per-frame failure and log one actionable reason. Camera cuts, loading transitions, FOV changes, and dynamic-resolution changes request an NR history reset.

## Performance and cache behavior

The path adds one optional neural evaluation and copies the existing depth/motion guides into shared resources. It adds no PIXL HLSL permutation, descriptor define, shader register, or C++/HLSL constant-buffer ABI change, so enabling it does not require a PIXL shader-cache rebuild. GPU cost and image quality remain runtime-test items and depend on the vendor model and output resolution.

## Validation

Static validation completed on 2026-09-01:

- canonical Release `PIXLRenderer` build: PASS;
- integrated `PIXL-Audit`: PASS (38 modules);
- no HLSL files or shader permutations changed;
- fail-safe normal-DLSS copy path retained.
- Photo Finish neural-source handoff uses a completed-frame serial and double-buffered shared output;
- neural and frame-generation depth/motion guides are isolated;
- normal Photo Finish remains the automatic fallback when neural capture is unavailable.

Runtime and visual validation are still required. Recommended first test:

1. disable or rename `renodx-dlss.addon64`;
2. select DLSS, SDR, and Frame Generation Off;
3. enable Neural Rendering and choose Natural; Frame Generation may be left off for the first A/B, then enabled for the combined-path test;
4. restart Skyrim;
5. confirm the log reports `Initialized DLSSNR 310.8... through PIXL DX12 sidecar`;
6. confirm the GUI's successful-frame counter advances;
7. test camera rotation, actor motion, foliage, particles, UI, loading, FOV changes, and dynamic resolution;
8. enter Photo Mode, press `Insert`, set `Neural Final Composite` to `READY`, select 8 or 16 fresh-frame accumulation, capture at Native and 2x, and confirm the log says `neural source on` plus `Photo Finish accumulation complete`;
9. switch to FSR/TAA and confirm the neural photo toggle is unavailable while normal Photo Finish still captures;
10. confirm disabling NR and restarting reproduces the normal DLSS baseline.

## Known limitations

- The runtime contract is private and intentionally version-gated.
- SDR only for the first validated implementation.
- Mutually exclusive with the RenoDX DLSS addon.
- The validated neural output resource is display resolution. Photo Finish can reconstruct a larger 2x/4x final image, but PIXL does not claim the private transformer itself is evaluating at 2x/4x.
- Combined Neural Rendering + Frame Generation and neural Photo Finish remain runtime validation items; compilation alone cannot prove visual or pacing quality.
