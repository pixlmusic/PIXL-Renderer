# Font and theme review — September 7

Scope: full source read of Fonts.cpp/h, FontSelector.cpp/h and ThemeManager.cpp/h; font-related Menu.cpp/Menu.h/RuntimeSettingsRenderer.cpp call sites only. This is not a full Menu/UI audit or an in-game result.

## Architecture and pipeline

Theme JSON → Menu normalization → font-role settings → deferred reload before ImGui frame → role/locale/optional preview atlas → ImGui DX11 device objects → overlay. Five actual roles are Body, Title, Heading, Subheading and Subtext; older ThemeManager schema comments incorrectly describe four. No scene shader, reconstruction input or game hook changed.

Inputs: theme files, installed font catalog, locale names, optional Windows CJK fonts, screen height, ImGui context and D3D11 device/context. Outputs: font atlas, cached role/preview pointers, resolved pixel sizes and signature. Locale enters the signature. Initial load occurs from Menu initialization; subsequent reloads are deferred by DrawOverlay, which requires no active frame/child. Preview fonts are requested only for the font tab and capped at 64 with three consecutive failures. Atlas clears invalidate preview caches. D3D resources are recreated via the existing ImGui backend; the existing GPU query wait remains. Device-loss/failed-retry behavior requires further integration work.

Source font assets live in distribution/Interface/PIXLRenderer/Fonts. PathHelpers relocates runtime presentation assets under Data/SKSE/Plugins/PIXL/Interface. Stage currently packages Jost and Sanguis; the picker discovers installed files, not every source family. Optional families were retained in source, not incorrectly classified as dead. CJK fonts are searched under WINDIR/Fonts (fallback Windows Fonts directory), not redistributed or downloaded.

## Five release investigations and changes

1. **Glyph-range lifetime — HIGH (resource lifetime), controlled correction.** Supplemental locale-name ImVector ranges were local to the merge block, destroyed before Build. Installed ImGui 1.92.6 header explicitly requires GlyphRanges arrays to persist for the font lifetime. The merge collection now has persistent storage, cleared only after the old atlas is cleared. Expected result: prevent dangling glyph-range reads in legacy range consumers. Small bounded locale metadata remains resident until next reload; no frame-loop allocation added. Existing backend/locale behavior preserved. Exact storage block tested with 20 real ImGui atlas builds; full locale picker/rendering still needs in-game tests.
2. **Reload preconditions and optional assets — LOW.** GetIO preceded the null-context check. It now follows that check; missing optional Windows font candidates are skipped before AddFontFromFileTTF. Prevents invalid context access and missing-file assertions in compatible debug backends. No change to installed font priority or ordinary rendering cost. Exact production precondition prefix tested with real ImGui: absent context, absent D3D pointers, active frame, successful gate and repeat entry.
3. **Legacy custom font metadata — LOW.** Legacy FontName changed the file but retained default Jost labels. Legacy body family/style now clear and derive from the file; explicit role labels remain respected. Derivation now precedes default filling for supplied files. Correct picker labels, unchanged actual selected font, negligible load-only work. Tests cover legacy/custom/default/explicit metadata and size bounds. No new settings keys.
4. **Catalog correctness/safety — LOW.** ExtraBold matched Bold first. Specific compact/spaced ExtraBold tokens now precede Bold. Both extension parsers reuse unsigned-byte-safe ToLowerCopy instead of signed-char tolower. UI ordering and non-ASCII filename safety improve without changing font assets. Native tests cover ranks and all 256 byte values. Catalog-by-value optimization was rejected for now: RuntimeSettingsRenderer retains its own catalog and only refreshes explicitly; no demonstrated per-frame scan/copy bottleneck.
5. **Theme save success reporting — LOW.** SaveTheme now checks the stream after close, reporting write/flush failure instead of success. No rendering or successful-save behavior change. Full native build validates compilation; a full disk-error injection test is still outstanding. This is not transactional saving: an interrupted overwrite can still damage an existing custom theme. Atomic temporary-write/replace with recoverable backup remains future work.
